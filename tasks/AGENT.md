# Памятка агенту: сначала ресёрч, потом код

Если в задаче есть выбор (библиотека, подход, формат, цифры «с потолка») — **не гадай и не бери
первое попавшееся**. Сначала исследование, потом решение, потом код. Это обязательно, а не «по
желанию».

## Протокол решения

1. **Сформулируй вопрос** одним предложением: плохо — «какую физику взять», хорошо — «какой движок
   для бросков d4–d20 в офлайн-PWA: вес бандла, WASM-инициализация, ConvexPolyhedron из вершин».
2. **Вебсёрч**: 2–3 запроса разными словами. Приоритет источников: официальные доки и спеки →
   исходники/CHANGELOG → сравнения с цифрами → статьи → мнения.
3. **Если вебсёрч недоступен** (403 из песочницы — бывает): обход через DuckDuckGo HTML
   (`https://html.duckduckgo.com/html/?q=...`) + `webfetch` конкретных страниц (Wikipedia,
   официальные доки, страницы пакетов). Каждый факт — со ссылкой и датой проверки.
4. **Таблица вариантов** (минимум 2, иначе это не выбор, а назначение): столбцы — критерии из §
   «Критерии» ниже, строки — варианты.
5. **Метод исключения**: вычёркивай варианты по одному, каждый с причиной в одну строку (« Cannon?
   нет: …»). Должен остаться один — самый выгодный и обоснованный именно для нашего случая. Если
   осталось два равных — выбирай проще/с меньшими зависимостями и фиксируй, почему.
6. **Запиши решение**: 5–10 строк в задачу или в `docs/*.md` (таблица + вердикт + ссылки). Будущий
   ты (или другой агент) должен понять ход мысли, не повторяя поиск.

## Критерии оценки (в порядке важности для нас)

1. **PWA-бюджет**: вес бандла/precache, офлайн без сети (см. PERF.md).
2. **Ноль бэкенда**: всё считается на клиенте, иначе — отдельное обоснование.
3. **Честность продукта**: ничего, что подрывает «честные дайсы» (подкрутки, непроверяемая магия) —
   instant reject.
4. **Зависимости**: меньше и стабильнее лучше; WASM/async-инициализация — минус для офлайна.
5. **Проверяемость**: можно ли покрыть тестом/замером (а не «верьте мне»).
6. **Цена владения**: кто будет поддерживать через полгода (мы же и будем).

## Что нельзя

- Брать числа/факты «по памяти» без пометки: непроверенное маркируй `[УТОЧНИТЬ]` или `[по памяти]`
  прямо в тексте.
- Выбирать «потому что популярно» без таблицы — популярность не критерий из списка выше.
- Тащить код с лицензиями, несовместимыми с проектом (AGPL — только смотреть API/доки, не
  копировать; см. COMPETITORS.md §4).
- Молча менять контракт (AST, API стора): сначала согласование через человека.

## Примеры как надо (уже в репозитории)

- `docs/STACK.md` — ванила против React/Vue: собственные замеры esbuild вместо чужих статей.
- `docs/BRANDING.md` — шортлист имён с таблицей проверок и отклонениями.
- `docs/COMPETITORS.md` — факты со страницы конкурента, не из головы.
