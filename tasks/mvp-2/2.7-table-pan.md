# 2.7 Пан камеры на столе: зажал фон → тянем по XZ (длинный ряд при зуме)

Статус: READY

## Цель

При зуме длинного ряда в кадре середина, а боковые кости — нет. Нужен жест: **зум (уже есть) →
зажать фон стола → тянуть пальцем/мышью → вид сдвигается по осям стола**, крайние кости становятся
видны. Короткий тап при этом по-прежнему бросок, драг по кости — вращение кости.

## Контекст

- Камера/контролы: `src/shared/three/table.ts` — OrbitControls, `enablePan = false` (L168),
  `enableRotate` только orbit-режим (L170), зум-зажим 0.55–1.4× в `frameCamera` (L252–253), damping
  0.08. `home` + `resetView`: после settle камера сама едет домой (вызов в `mobile-table.ts` L1107)
  — это существующее поведение, сохранить.
- Жесты виджета: `src/widgets/mobile-table/mobile-table.ts` L1117–1158 — `pointerdown`: тап по кости
  (<8px / <500мс) = бросок, драг по кости (≥8px) = `spinDie`, **драг по фону сейчас ничего не
  делает** (комментарий L1118). Всё мертво во время `rolling`.
- Верх экрана = мировая **+Z** (см. `layoutSlots` в `features/table-roll/table-roll.ts`) — оси пана
  XZ, не XY.
- Конфликт: OrbitControls навешивает свой `pointerdown` в конструкторе (table.ts) — раньше подписок
  виджета. Переключать `controls.enablePan` внутри `pointerdown` виджета задним числом **не
  сработает**: к тому моменту OrbitControls уже принял решение. Гейт надо делать либо своим
  listener'ом раньше/в capture-фазе, либо паном вне OrbitControls.
- Границы кадра: `fitHz`/`fitHx`, `setFit(hx, hz)` — за контент-бандс камеру не пускать (иначе юзер
  утащит стол в пустоту и не найдёт).

## Варианты реализации (ресёрч-first, выбрать один)

- **A. Свой пан в виджете** (по образцу `spinDie`): драг по фону (`dieId == null`) двигает
  `controls.target` + камеру в view-плоскости (пиксели → мир по дистанции/fov), с клампом по
  контент-бандсам. OrbitControls не трогаем — конфликтов нет. Math (включая кламп) вынести чистой
  функцией в `features/table-roll/` и покрыть тестами.
- **B. OrbitControls pan** (`enablePan = true`, `mouseButtons.LEFT = PAN`, `touches.ONE = PAN`) с
  гейтом «жест начался не на кости» — решать порядок listener'ов (capture-фаза) и конфликт со
  `spinDie`.
- **C. Пан только после зума** (>1× от minDistance): на стартовом кадре фон-драг ничего не делает
  (меньше случайных сдвигов), при зуме — работает. Комбинируется с A или B.

## Требования

1. Драг по фону стола с зажатием сдвигает вид в плоскости XZ стола (верх экрана = +Z),
   пропорционально движению пикселей и текущей дистанции камеры.
2. Кламп: `controls.target` не выходит за контент-бандс (с запасом ~0.5); зум-лимиты 0.55–1.4× и
   `resetView` не ломаются.
3. Драг с кости = `spinDie` (не пан); тап по кости = бросок; тап по фону (<8px) = ничего; во время
   `rolling` жесты мертвы; пинч/колесо-зум не меняется.
4. На время `resetView`-доводки пан глушится (существующий механизм «контролы глушим»).
5. Мобилка: один палец по фону = пан; шторка/кнопки шапки-футера на канве не страдают. Десктоп:
   левая кнопка мыши по фону = тот же пан.

## Приёмка

- Бросок `8d10` (длинный ряд), зум до упора → зажать фон и сдвинуть вправо — правый край ряда в
  кадре; отпустить — кости на месте, без рывков (damping).
- Тап по фону ничего не делает; тап по кости бросает (`e2e/m-table.spec.ts` зелёный); драг по кости
  вращает кость.
- Попытка утащить вид за край — упирается в кламп, стол не теряется.
- Unit-тесты на math пана (screen→world, кламп) зелёные; `tsc`, eslint, `npm test` чисто; 0 ошибок
  консоли в Playwright-чеке.
