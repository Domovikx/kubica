# 2.25 Превью ссылки в Telegram: og:image + картинка-превью

Статус: READY

## Задача от пользователя

«Надо в таски сформировать задачу: когда пользователи пересылают друг другу в Telegram, например,
ссылку на приложение — должна делаться вместе со ссылкой некое превью. Типо как сделано в
`C:\Users\Domo\AppData\LocalLow\Owlcat Games\Warhammer 40000 Rogue Trader\UnityModManager\W40KRTAudioDirectMod\`
— где-то там мы что-то похожее делали, можешь поресёрчить. Но нам нужна была ещё и картинка — такая
превьюшка, тоже надо подумать, что и как сделать.»

## Цель

Когда ссылку на Kubica кидают в Telegram (и в других мессенджерах — базово бесплатно), у сообщения
должна появляться полноценная карточка: заголовок, описание и **картинка-превью**, а не голый текст
ссылки. Превью — витрина продукта для «сарафана»: люди пересылают ссылку друг другу, и первое
впечатление делается по этой карточке.

## Контекст (что есть сейчас; проверено чтением, 2026-10-08)

- `index.html:18-34` — og:теги **уже есть частично**: `og:type`, `og:locale`, `og:title`,
  `og:description`, `og:site_name`, `twitter:card` = `summary` + twitter:title/description.
  **`og:image` и `twitter:image` отсутствуют** → Telegram показывает текстовую карточку без большой
  картинки (точный фортменат покажет ресёрч).
- `index.html:17` — `canonical` указывает на репозиторий (`https://github.com/Domovikx/kubica`), а
  не на приложение; `og:url` нет. Боевой URL приложения — `https://domovikx.github.io/kubica/`
  (`README.md:3`, деплой — `.github/workflows/deploy.yml`, GitHub Pages).
- Тексты og: заголовок про «D6 16 мм: FreeCAD vs OpenSCAD vs CadQuery» — тональность унаследована от
  среза CAD-статьи, а сейчас в приложении стол бросков (продукт сдвинулся). Править ли тексты —
  вопрос ресёрча.
- Прецедент «где-то уже делали»: в указанном репо `W40KRTAudioDirectMod` по grep (md/py/cs,
  «preview/og/telegram/превью») **ничего похожего не найдено** (ресёрч 2026-10-08) — уточнить у
  человека, в каком именно проекте это было, и посмотреть там.
- Картинки-логотипа/брендинг есть: `docs/BRANDING.md`, водяной знак Kubica в приложении
  (2.17-social-star).

## Что сделать (ресёрч, по протоколу `tasks/AGENT.md`)

1. **Механика Telegram** (вебсёрч, факты со ссылками и датой сверки):
   - какие теги читает link-preview (`og:image`, `twitter:card=summary_large_image`, `og:url`,
     `og:title/description`), абсолютные ли нужны URL, грузится ли картинка без JS;
   - размеры/пропорции и вес картинки для большой карточки (стандарт ~1200×630 vs квадрат — что
     отдаёт Telegram, лимиты веса);
   - кэширование: как перезалить превью после правки (пересборка кэша Telegram — бот/команда),
     сколько живёт старое;
   - погрепать/вспомнить, в каком проекте «похоже уже делали» (вопрос к человеку, см. контекст).
2. **Откуда брать картинку — таблица вариантов ≥2, метод исключения, вердикт ±:**
   - (а) статический PNG в `public/` — ручная сборка из ассетов брендинга (Figma/Inkscape);
   - (б) автоматический скриншот приложения (Playwright, штатный кадр стола с костями) со
     скриптом-регенерацией — превью всегда актуально к UI, но хрупко к смене дизайна;
   - (в) рендер красивого кадра 3D-сцены (тот же Playwright/штатный вьювер);
   - (г) внешний генератор/сервис картинок — **сверить с критерием «ноль бэкенда» и PWA-бюджетом**
     (`tasks/AGENT.md` §Критерии), скорее всего instant reject, но проверить.
   - учитывать: текст на картинке (название/слоган читаются в мессенджере), адапт под пропорции из
     пункта 1, вес, кто будет регенерировать при смене UI.
3. **Согласовать с человеком** (question-tool после ресёрча): тексты og (оставить CAD-тональность
   или переформулировать под стол бросков), канонический URL (github.io vs ссылка на репу), вариант
   картинки из таблицы.
4. Реализация: статические теги в `index.html` (crawler JS не выполняет), картинка в `public/` +
   путь в og:тегах; при выборе варианта (б)/(в) — скрипт генерации рядом с существующими
   инструментами (`tmp/check/` для чекеров — по прецеденту `2.20`).

## Приёмка

- [ ] `index.html`: `og:image` (абсолютный https-URL), `og:url`, `twitter:card` =
      `summary_large_image` + `twitter:image`; og:тексты согласованы с вердиктом ресёрча.
- [ ] Картинка по абсолютному URL отдаётся с GitHub Pages (проверка прямым fetch до и после деплоя).
- [ ] Инструкция проверки в Telegram выполнена на живой ссылке: свежий пост/пересылка показывает
      большую карточку с картинкой (со сбросом кэша превью — способ из ресёрча).
- [ ] PWA-бюджет не вырос: картинка-превью не добавлена в precache сервис-воркера, офлайн-режим не
      задет.
- [ ] Если выбран автоматический вариант (б)/(в) — скрипт регенерации воспроизводим одной командой и
      задокументирован.
- [ ] Полная батарея перед сдачей: `npx tsc --noEmit`, `npx eslint src/`, `npm test`,
      `npm run build`; при правках UI — Playwright-чек без ошибок консоли.
