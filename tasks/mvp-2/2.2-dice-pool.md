# 2.2 Пул костей: степперы + формула-бар + пресеты + бросок пула

Статус: QUEUED (ждёт 2.1 — контракт `RollExpr` из `entities/dice-notation/`).

## Цель

Пользователь собирает пул (степперы количества или строка формулы), жмёт бросок — все кости пула
бросаются в одном физическом мире, результат — сумма + разбивка.

## Контекст

- `docs/PLAN.md` → Трек A, задача 2.2; `docs/UX_ROLL.md` §1 (паттерны A–D).
- Есть: `features/roll-dice/` (стор `idle/rolling/settled`, `quickRoll`, физика cannon-es с
  очередью, `readout`), `entities/roll-history/`.
- Пресеты (фиксированные выражения): Advantage `2d20kh1`, Stats `4d6-L` (синоним `4d6dl1`), Fireball
  `8d6`.

## Требования

1. **Симуляция пула** — `features/dice-pool/pool.ts`:
   - вход: `RollExpr` (из 2.1) + сид/RNG;
   - каждая кость пула бросается физическим миром (переиспользовать
     `createPhysicsWorld`/`quickRoll`-механику, НЕ плодить второй движок);
   - `kh/kl/dh/dl` применяются к выпавшим значениям пула;
   - выход: `{ total, parts: [{ die, value, display, kept: boolean }] }`;
   - d100 считается как одна кость 1..100 (пара d10+d% — только в 2.5).
2. **Стор пула** — `features/dice-pool/pool-store.ts`: состояние пула (выражение + количество), фазы
   как в roll-store, токен гонки как там же.
3. **UI** — `widgets/roll-panel/`: степперы d4…d20 (+/−), поле формулы (валидация через парсер 2.1,
   ошибка — текст `NotationError`), 3 кнопки пресетов. Тап по кости (существующий) — бросок `1dN`.
4. **История** — расширить `HistoryEntry` полем `parts` (опционально, чтобы старые записи читались):
   сумма + разбивка.
5. Тесты: симуляция `2d20kh1` (kept = max), `4d6dl1` (сумма без минимума), модификаторы, `d100` в
   диапазоне; UI-логика без DOM — моки драйвера (как в `roll-store.test.ts`).
