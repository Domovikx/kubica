# 2.20 Настройка масштаба интерфейса (100–200%) в меню-бургере

Статус: DONE (ресёрч, реализация, проверки, визуальный контроль; коммит по просьбе пользователя)

## Задача от пользователя

«Следующая итерация и тудушка — продумать механизм масштабирования. Это так просят пользователи.
Где-то в меню нужно сделать настройку масштабирования интерфейса. Вебсерчим бест-практики и
реализуем в меню, которое через бургер открывается.»

## Ресёрч (веб, 2026)

websearch-провайдер (Exa) — снова 403; прямой fetch источников:

- **WCAG 1.4.4 Resize Text (AA)** — текст увеличивается до 200% без потери контента/функций;
  промежуточные шаги между 100% и 200% тоже без потерь. Техника **G178** — «контрол на странице,
  позволяющий пользователю увеличить весь текст до 200%» — это ровно наш фичер. Ловушки: F69
  (обрезка/наложение при 200%), F94 (некорректные viewport-юниты для текста).
- **WCAG 1.4.10 Reflow (AA)** — без горизонтальной прокрутки на ширине 320 CSS px (эквивалент 400%
  зума) — проверяем на каждом шаге масштаба.
- **WCAG 2.5.8 / 2.5.5** — тапы ≥24 (AA) / ≥44 (enhanced): тап-боксы масштабируются вместе с
  текстом, на 100% остаются ровно 44.

Варианты механизма и выбор:

- CSS `zoom` на UI-обёртке (пропорционально всё сразу) — **отклонён**: замером (playwright-пробники
  `tmp/check/zoom-probe.mjs`, `zoom-pixel.mjs`) выяснилось, что rect'ы обёртки и детей дают разные
  системы координат, vw внутри умножается неочевидно — хрупко для чекеров и `fitHeadStar`.
- Множитель `--ui-scale` на токенах — **выбран**: детерминировано, предсказуемо для замеров, кости
  (3D) не зависят (их масштаб задаёт камера — фидбэк «кости ОК, интерфейс мелкий»).

Шаги: **100 / 125 / 150 / 175 / 200%** (WCAG 1.4.4/G178: доступен путь до 200%).

## Реализация

- `src/features/ui-scale/ui-scale.ts` — `UI_SCALES`, `uiScale()`/`setUiScale()` (персист
  `dice-uiscale` в localStorage, паттерн `dice-muted`/`dice-power`), `applyUiScale()` пишет
  `--ui-scale` на `<html>`; битое значение → 1, исключения localStorage не валят масштаб.
- `src/widgets/mobile-table/mobile-table.css`:
  - `:root { --ui-scale: 1; --tap: calc(44px * var(--ui-scale)) }`;
  - все 12 токенов `--fs-*`/`--icon-*` обёрнуты в `calc(clamp(...) * var(--ui-scale))`;
  - тап-боксы на `--tap`: `.mtableIcon`, `.mtableChip`, `.mtableHintCta`, `.mtableStep`,
    `.mtableOk`, `.mtableWide`, `.mtableSocial`; `.mtableN`/`.mtableName` — `calc(28/40px * …)`;
  - страховки рефлоу (доказаны чекером на 150–200%): `.mtableRow { flex-wrap: wrap }` — степперы
    уезжают на вторую строку; `.mtableSectionHead { flex-wrap: wrap }` — ссылка «Очистить» уходит на
    свою строку, а не за экран (был вылезание 323>320);
  - новый ряд `.mtableScaleRow` + пилюли `.mtableScale` (`.on` — акцент, как у `.mtableWide.on`).
- `src/widgets/mobile-table/mobile-table.ts` — секция «Масштаб интерфейса» в drawer между «Звук и
  вибрация» и «О Kubica»: заголовок + 5 пилюль с процентами; клик → `setUiScale` + `syncScale`
  (класс + `aria-pressed`) + `refreshChrome()` (в нём `fitHeadStar` пересчитывает шапку под новые
  боксы) + тост «Масштаб N%» + `vibrate(15)`; инициализация `applyUiScale(uiScale())` в начале
  `mountMobileTable`.
- Тест: `src/features/ui-scale/ui-scale.test.ts` — 6 vitest (дефолт, набор шагов, roundtrip, битое
  значение, localStorage падает, apply без document).

## Проверки

- `node tmp/check/ui-scale.mjs` → **ALL OK**: на 320 все 5 шагов — токены точно ×шаг (база
  14/15/16/17/18/20 → 200%: 28/30/32/34/36/40), нет вылезания за экран (1.4.10), тапы ≥44, центр
  пары 160±4, активный чип + `aria-pressed`, персист после reload (остаётся 200%), возврат на 100%;
  на 390 — проход @150%; консоль чиста; шоты `tmp/shots/scale/` (320-{100..200}-{drawer,sheet},
  390-150-drawer).
- Регресс после правок CSS: `type-scale`, `add-icon`, `hint-v2`, `hint-cta2-shots`, `social-shots`,
  `hint-align`, `like-fit-probe` — **все ALL OK** (тапы 44 = `--tap` на 100%).
- Визуальный контроль (ASCII-превью, обход сломанных аттачей): `320-200-sheet` — шторка целиком:
  чипы 2×2, степперы перенеслись на вторую строку, «Сохранить сет» в кадре, без обрезки;
  `320-200-drawer` — секции читаемы, «Очистить» перенесён, пилюли 100…200%, тост «Масштаб 200%».
- Полный прогон перед коммитом: `npm run lint`, `npm test`, `npm run test:e2e`.

## Наблюдения

- На 320@175–200 шапка теснеет: `fitHeadStar` (уже существующий замер) первым делом прячет звук,
  затем ряд Star — GitHub-ссылка при этом всегда остаётся в шторке («О Kubica»/соцсети).
- Шоты требуют паузы ~200ms после смены состояния: снимок сразу после `waitForSelector` брал
  устаревший кадр (файл меню == файл шторки) — в чекере добавлено `waitForTimeout(200)`.
- Декоративный водяной знак и 3D-поле намеренно НЕ масштабируются.
