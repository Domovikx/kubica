# i18n kubica на 10 языках (список языков — из po-словаря NeonTranslator)

Статус: READY

## Задача от пользователя

«C:\Program Files (x86)\Steam\steamapps\common\Third Crisis Neon Nights\NeonTranslator\po нужно
посмотреть какие там есть языки перевода. нам надо тут организовать i18n для этих же языков. запиши
пока это в задачи, сейчас не делаем просто оформляем задачу, вебсерчим и ресерчим, расписываем
задачу.»

## Цель

Когда я открываю kubica с телефона из любой из 10 поддерживаемых стран, я хочу видеть интерфейс на
своём языке (тот же список, что у словаря игры NeonTranslator), сохранённый выбор и понятный
переключатель в меню. Критерий «стало лучше»: UI без единого «зашитого» русского текста в
компонентах, каталоги 10 языков, fallback на русский, e2e/чекеры зелёные.

## Контекст (что есть сейчас)

### Источник списка языков (po-папка игры, аудит 2026-10-11)

- Путь: `C:\Program Files (x86)\Steam\steamapps\common\Third Crisis Neon Nights\NeonTranslator\po`.
- Языки: **de, es, fr, it, ja, ko, pl, pt, ru, zh** (+ шаблон `template.pot`); формат gettext .po,
  UTF-8, `msgctxt "ui"`, ~33 272 msgid на язык (словарь самой игры).
- Заполненность (для справки, kubica эти переводы НЕ использует): ru ~56 % переведено, de ~33 %,
  fr/ja/zh ~0 %; есть `autofill_blocklist.txt` (human-review-исключения) и `triaged.txt`.
- Вывод: из po берём **только список языков** (и опыт пайплайна пользователя), сами игровые строки к
  UI стола отношения не имеют.

### Стек kubica (важно для выбора i18n-решения)

- Vite 8 SPA + React + RTK + StyleX; PWA; мобилки — основной сценарий; бандл и lazy-load важны
  (физика cannon-es уже ленивится динамическим import).
- UI сейчас целиком русский, разбросан литералами по tsx (Head/Drawer/Sheet/MusicCard, тосты,
  aria-labels, title, empty-state, `dangerouslySetInnerHTML`-строки иконок с текстами).
- Хранение состояния: localStorage (ключи: `mtable.*`-префикс у сохранений); язык логично хранить
  рядом (например, `mtable.lang`).
- Контракты, которые нельзя ломать: маркеры `.mtable*`, `data-testid`, `data-phase`, пиксель
  (computed-diff) — переводы НЕ меняют разметку/классы, только текстовые ноды.

### Инвентаризация переводимого (предварительная, уточнить при реализации)

- Кнопки/заголовки: Head (burger/add/sound/music/Star), Sheet (Выбор костей, Быстрые/Мои,
  степперы-подсказки, «Сохранить сет»), Drawer (История/Очистить/Точно?, Сила броска, Звук и
  вибрация, Масштаб, О проекте, Соцсети), MusicCard, Hint, Foot, тосты («Масштаб %», «Набор
  сохранён/удалён/обновлён», офлайн-тост), aria-labels/title.
- Динамические: `Масштаб {n}%`, `Оценить репозиторий…, звёзд: {n}`, счётчик звёзд, состав набора
  (форматирование `shortSet`/`formatParts` — оставить как есть, это коды костей, не фразы).
- Счётчики: грубый порядок ~100–150 строк/ключей на язык (уточнить скриптом-аудитом).

## Ресёрч (веб-поиск 2026-10-11)

- Обзоры 2026 (pistack, auto18n, laoujin Atlas, Phrase): три игрока — **react-i18next** (8.6k ⭐,
  экосистема, JSON-каталоги, lazy-load), **FormatJS/react-intl** (14.7k ⭐, ICU MessageFormat),
  **LinguiJS**; для Vite SPA отдельно выделяют **Paraglide** (compile-time, самый малый бандл).
- Рекомендация ландшафта: Vite SPA → Paraglide (минимальный бандл) или react-i18next (зрелая
  экосистема); runtime-dictionary-решения гибче, compile-time — меньше runtime.
- ICU/MessageFormat полезен при сложных плюрализациях; у kubica плюрализация почти не нужна («звёзд:
  N», «Масштаб N %» — интерполяция, без gender/case-цепочек).

### Варианты (выбрать при реализации / согласовать)

1. **react-i18next + JSON** (гипотеза-кандидат): `src/i18n/index.ts`, каталоги
   `src/i18n/locales/{ru,de,es,fr,it,ja,ko,pl,pt,zh}.json` лениво через `import()`, хук
   `useTranslation`, TS-ключи (i18next-parser или ручной type). Плюсы: экосистема, docs, interceptor
   для aria; минусы: +деп к бандлу (~кб), рантайм-lookup.
2. **DIY-хук** (гипотеза-минимализм): `useT()` + статические JSON-модули, fallback-цепочка
   `lang → ru → ключ`. Плюсы: 0 зависимостей, полный контроль; минусы: свои интерполяции/plural,
   самописные типы. Объём UI мал — может хватить.
3. **Paraglide JS** (compile-time): месседжи в коде как функции, tree-shaking, но новая
   инфраструктура/плагин, переучивание кодовой базы — риск для существующего StyleX-пайплайна.

### Вопросы ресёрча (согласовать до реализации)

- Формат каталогов: чистый JSON (i18next) vs gettext-.po-совместимость (пайплайн NeonTranslator
  пользователя: po ←→ YAML/тулзы)? Если хочется po — gettext-parser/gettext-runtime как бридж.
- Кто переводит: LLM-перевод (агент) с пост-читкой человеком? Ревью пользователем по языкам?
- Переключатель: секция «Язык» в Drawer (как «Масштаб»), автодетект `navigator.language` при первом
  визите + ручной выбор, хранение в localStorage.
- Объём: только видимый UI или и SEO (`<html lang>`, title/description), PWA-манифест, alt/aria?
- Проверка машинного перевода ja/ko/zh: вертикальные/широкие шрифты, переносы в кнопках (fit-логика
  Head не должна ломаться — длины строк отличаются).

## Что сделать (порядок шагов)

1. Инвентаризация: скрипт-аудит grep литералов в tsx (кириллица в src/) → таблица ключей с
   контекстом (компонент, файл:строка, динамическая/статическая); согласовать с человеком список
   ключей и финальный выбор варианта (react-i18next vs DIY vs Paraglide vs po-мост).
2. Каркас: `src/i18n/` (провайдер/хук, lazy-каталоги 10 языков, fallback ru, persist в localStorage,
   детект браузера).
3. Точечная интернационализация волнами: Head → Drawer → Sheet → MusicCard/Hint/Foot → тосты →
   aria/title; после каждой волны — tsc/eslint/vitest.
4. Переключатель языка в Drawer (секция по аналогии с масштабом), `<html lang>` синхронизация.
5. Переводы: сгенерировать 9 языков (дефолт — ru как источник), человек проверяет ключевые строки
   (CTA, aria); для ja/ko/zh — превью в браузере (переносы/размеры).
6. Тесты: unit (fallback, интерполяция, persist), e2e (переключение языка меняет заголовок
   шапки/дровера, reload сохраняет выбор), чекеры + computed-diff на исходном ru (пиксели без
   изменений), батарея 9 чекеров.

## Приёмка

- [ ] Ни одного «зашитого» русского литерала в tsx (grep кириллицы в `src/` — только
      `src/i18n/locales/ru.json` и комментарии).
- [ ] Каталоги 10 языков (de, es, fr, it, ja, ko, pl, pt, ru, zh), fallback: любой язык → ru → ключ.
- [ ] Выбор языка: автодетект при первом визите, ручной переключатель в дровере, persist
      (localStorage), переживает reload (e2e).
- [ ] `<html lang>` соответствует выбранному языку.
- [ ] Полная батарея: tsc/eslint/vitest/npm run lint/build/e2e 30+/чекеры 9/computed-diff на ru без
      изменений (переводы не двигают пиксели исходного состояния).
- [ ] Бандл: языковые каталоги не в основном chunk (lazy import), проверить dist размер.

## Вне рамок (out of scope)

- Перевод словаря самой игры (po-файлы NeonTranslator) — берём только список языков.
- RTL-языки (арабский/иврит) — в списке нет.
- Перевод кодовых/технических строк: форматы костей («2d6+3»), имена файлов, CSS-токены.
- Веб-апп перевода / CMS — переводы живут в репозитории JSON.
- Автоматический ре-экспорт из po-пайплайна игры — опциональный бридж, не блокер.
