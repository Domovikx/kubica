# 2.23 Отдельное музыкальное меню (по кнопке `mtable-music`)

Статус: DONE (2026-10-08; коммит d960a87 — карточка музыки по кнопке шапки)

## Цель

Кнопка `mtable-music` в шапке открывает **отдельное меню музыки** (выделенный вход в управление
фоном), а не только тогглит воспроизведение напрямую. Фидбек пользователей (2026-10-08): «хотят
отдельное меню для музыки, чтобы оно открывалось по mtable-music».

### Вопросы

1. **Форма меню музыки**: поповер, прикреплённый под кнопкой `mtable-music` / центрированная
   карточка-модалка (как существующие шит и дровер) / bottom sheet / отдельный экран.
2. **Поведение кнопки шапки**: тап = открыть меню (тоггл переезжает внутрь) или тап = тоггл (как
   сейчас) + долгий тап/вторая кнопка = меню.
3. **Судьба секции «Фоновая музыка» в бургер-дровере**: переезд, дубль или ссылка.
4. **iframe-контракт 2.22**: музыка продолжает играть при закрытом меню.

### Метод исключения (от наименее подходящего)

1. **D. Отдельный экран** — нет: ломает iframe-контракт (unmount → `disposeMusic`), требует
   навигации, которой в PWA нет, и теряет контекст стола (NN/g №5).
2. **B. Поповер под кнопкой** — нет: Apple HIG прямо запрещает поповеры в compact-видах (№1), наш
   мобайл-фёрст стол = compact; в коде нет anchor-инфраструктуры; iframe-плеер по ширине не влезает
   в «small amount of functionality».
3. **C. Bottom sheet** — нет: годен по гайдам (№4, №5), но даёт нулевой выигрыш против A при новом
   CSS/жестовом паттерне; свайп-закрытие добавляет случайных закрытий (NN/g №5), а фон видно хуже,
   чем у центрированной карточки.
4. **A. Центрированная карточка-модалка** — остаётся (см. вердикт).

### Вердикт: вариант A — карточка-модалка по образцу шита/дровера

**Плюсы:**

- Ноль новой инфраструктуры: третий оверлей вплетается в существующие
  `openSheet`/`openDrawer`/`closeOverlays` (взаимное исключение с шитом и дровером уже есть, HIG
  «one sheet at a time» №6 выполняется).
- Контракт 2.22 сохраняется физически: `musicHost` остаётся в DOM с `display:none`, слайс `music.ts`
  не трогаем.
- Предсказуемо на 320px и на `--ui-scale` 150–200% (та же геометрия, что у двух существующих
  оверлеев), e2E пишется по образцу существующих музыкальных тестов.

**Недостатки:**

- Модальность: пока меню открыто, стол не интерактивен (для 2–3 быстрых настроек — приемлемо, тоггл
  play/pause остаётся в шапке рядом).
- Нет визуального якоря «выросло из кнопки» — снимается заголовком «Фоновая музыка» и тем, что
  кнопка шапки помечена `aria-haspopup`.
- Решение перестанет быть верным, если меню превратится в «now playing» с большим контентом (тогда —
  bottom sheet/отдельный экран).

### Судьба секции в дровере — варианты (вопрос человеку)

- **(i) Переезд** (рекомендация): секция `mtable-music-section` уходит из дровера в новое меню —
  один источник правды, дровер легче; синхронизация `onMusicChange` уже одна на оба тоггла.
- **(ii) Дубль**: секция остаётся + копия в меню — два места, синхронизация есть, но дубль
  интерфейса и лишние селекторы в e2e.
- **(iii) Ссылка**: в дровере строка «Фоновая музыка →», открывающая меню (паттерн Android Settings)
  — компромисс, +1 тап для тех, кто зашёл из меню.

### iframe-контракт 2.22 (закрыт фактом)

Контракт = «хост iframe живёт в DOM, `display:none` допустим, уничтожать нельзя» (код
`music.ts:303`, комментарий mobile-table.ts:779–782). Любая форма меню его выполняет, **если при
закрытии не чистится `innerHTML` оверлея**, в котором лежит `musicHost`. При переезде секции хост
переносится как есть (один `createElement`-блок, `syncDrawerMusic` переименовывается); слайс и
стейт-машина не меняются. Если секция остаётся в дровере дублем — двух хостов быть не должно (плеер
один, хост один; второй «место» — только ссылка/тоггл).

### Сомнения

**Сняты:**

- «Поповер под кнопкой — нормально для мобайла» → нет: Apple HIG compact = sheet, UIKit адаптирует
  поповер в шит (источники 1, 2).
- «Material-menu (список) подходит под тоггл+слайдер» → нет: menu по спецификации — список
  строк-действий (источник 3); для контролов — карточка/sheet.
- «Переезд секции сломает iframe/слайс» → нет: слайс от UI не зависит, хост переносимый; контракт =
  не уничтожать хост (код).
- «Нужна новая навигация для отдельного экрана» → подтверждено отсутствием роутера в проекте
  (вариант D исключён).

Дополнительные решения по ARIA (2026-10-08): у кнопки шапки убран `aria-pressed`, добавлен
`aria-haspopup="dialog"`, label статичный «Фоновая музыка» (состояние — иконка `on` и тоггл внутри
карточки); при недоступном YouTube кнопка сохраняет `aria-disabled=true` с пояснительным label, но
тап всё равно открывает карточку (объяснение — внутри, тоггл отключён). Отдельного undo-toast нет;
закрытие по клику на контрол — tap-based dirty (общий helper `wireDirty` с 2.24).
