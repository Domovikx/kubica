### 320px: где ★ уступает место

Арифметика (head padding 12×2, grid gap 10×2, ctl gap 10×2): на 320 доступно 276px под центральную
ячейку; ★ + два gap'а + бургер = 108px, то есть под подпись «+» остаётся 168px, а полный состав «2d4
2d6 2d8 2d10 d12 d20» — 225px. Влезить вместе не может физически (333 > 276), а резать состав
(ellipsis) и сужать пару запрещено.

Решение — **динамическое `fitHeadStar()`** (`mobile-table.ts`): ★ показана по умолчанию и
скрывается, только если после раскладки её край или край бургера вылезают за контент-бокс шапки;
вызывается в конце `refreshChrome` и в `resize()`. Поведение (замер `tmp/check/star-fit-probe.mjs`):

| Состояние на 320         | ★            | Пара «+»/бургер     | h-scroll |
| ------------------------ | ------------ | ------------------- | -------- |
| пусто / `d4` / `d4 d6`   | видна        | цела                | нет      |
| `d4 d6 2d8 2d10 d12 d20` | скрыта       | цела (burger ≤ 290) | нет      |
| после «Убрать все»       | возвращается | цела                | нет      |

На 390/768 ★ на месте **всегда** (состав + ★ = 333 ≤ 346 на 390, star.x = 28), на пустом столе — на
всех ширинах. Ссылка на репо при этом остаётся в шторке всегда — ★ в шапке это ускоритель, а не
единственная точка входа.

### Счётчик «0»

`showStars(n)` → `starCount.hidden = n < 1`, при скрытии `textContent = ''` (цифры не тащит ни в
DOM, ни в aria), затем `syncStarAria()`:

- `0` → мета-счётчик скрыт, строка-ссылка «Оценить репозиторий» видна всегда;
- `≥1` → мета с цифрой, aria проговаривает «звёзд: N»;
- offline/ошибка API → прежнее правило (скрыт, без спиннера);
- в шапке — всегда только иконка, цифры не бывает.

| Ширина | empty                  | mid (`2d4 2d6 2d8 2d10`) | full (весь состав)                          | cleared       |
| ------ | ---------------------- | ------------------------ | ------------------------------------------- | ------------- |
| 320    | виден 264..308, dxCx 0 | виден 264..308, dxCx −13 | **скрыт**, ctl 22..301 центрирован, dxCx +2 | виден, dxCx 0 |
| 390    | виден 334..378, dxCx 0 | виден, dxCx 0            | виден 334..378, dxCx −11                    | виден, dxCx 0 |
| 768    | виден 688..732, dxCx 0 | виден, dxCx 0            | виден 688..732, dxCx 0                      | виден, dxCx 0 |

`hScroll:false` во всех 12 состояниях; `pairGap` всегда 10.

- **320 + полный состав — лайк физически не влезает**: 24 (паддинги) + 20 (gap'ы) + 44 (лайк) + 98
  (пара) + 225 (текст) = **411 > 320**. Резать состав (ellipsis) и пару запрещено (2.15), поэтому
  лайк честно уступает — ссылка на репо остаётся в шторке.
- Сдвиг пары: центр заморожен на пустом столе (±3px), с составом — до −11px на 390 (занятые 44px под
  лайк в правой трети; граница допуска в чекере — 14px). На 320 со скрытым лайком пара снова
  центрируется (dxCx +2).

## Итог (фаза 6): адаптивный водяной знак

  вертикальный (≤2/3) → 90° (кусочно-линейно между); длина надписи = `min(availW/cos, availH/sin)`
  (без переполнения под поворотом), pad = `min(48, max(16, 6% от меньшей стороны))`, шрифт меряется
  при 100px и масштабируется под длину; вызовы — `requestAnimationFrame`, `fonts.ready`, `resize()`
  рядом с `fitHeadStar()`.
