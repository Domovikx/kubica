### Метод исключения (от наименее подходящего)

1. **2. Pending** — вычёркиваем первым: цена реализации наивысшая (staging всех 8+ настроек,
   неоткатываемые действия, сломанные контракты 2.20/2.22), HIG требует пару Done+Cancel (против
   фидбека об одной кнопке), при этом вся модель продукта — live-применение (инвентаризация в
   «Контексте»); подтверждение discard на каждый выход из меню (№1, №3) — накладно.
2. **3. Гибрид** — второй: не решает общую задачу (undo только последнего действия, отдельная
   undo-логика на каждый тип), объём близок к pending при меньшей ясности; snackbar остаётся
   опциональным усилением для точечных destructive-действий, а не каркасом.
3. **1. Сигнал** — остаётся.

### Вердикт: вариант 1 — чистый сигнал «Готово» (live + dirty-трекинг)

**Решение (5–10 строк):** Изменения остаются live (как сейчас). Открытие меню сбрасывает dirty-флаг;
первый тап-изменение в любом из меню (шит/дровер/будущее музыкальное из 2.23) — морф крестика в ✓:
кроссфейд/поворот ~160ms; при `prefers-reduced: reduce` — мгновенная смена. `aria-label`/title
переключается синхронно (в коде уже есть прецедент динамического label — `syncMusic`), финальный
текст — «Готово», начальный — «Закрыть». Тап по ✓, backdrop, Escape — закрывают без подтверждений
(изменения уже применены, ничего не теряется). Никакого staging. Морф работает во **всех** трёх
меню, backdrop/Escape остаются чистым dismiss. Pending — вернуть, только если появятся операции,
которые нельзя применить live (тогда — точечно для них, не глобально).

**Плюсы:** минимальная цена (нет staging); честность label «Готово» ≠ «Применить»; все пути закрытия
безопасны (NN/g «save, then out» №2); контракты 2.20/2.22 сохраняются; e2e пишется просто (изменение
→ ✓ → закрытие без потерь).

**Минусы/границы применимости:** ✓ без staging мягко «льгёт» обещанием commit — снимается label'ом;
универсального отката нет (есть точечные «Убрать все», повторные тапы, двухтап для истории);
перестаёт быть верным, если появятся отложенные/невалидируемые операции (тогда — pending для них
точечно).

### Сомнения

**Сняты:**

- «✓ означает commit → нужен pending» → нет: у live-применения есть прямой прецедент — фильтры Etsy
  = Done, а не Apply (NN/g №2), Material Settings live (№1).
- «backdrop/Escape при грязном состоянии = потеря работы» → нет при сигнале: изменений к откату не
  существует; подтверждения discard нужны только в pending (№1, №3) — там и будут.
- «нужен официальный морф-прецедент» → канонического X→✓ нет (№6) — это не запрет, а отсутствие
  канона: морф безопасен при честном label и aria.
- «меню нужно грязнить все разом» → нет: dirty пер-меню (открытие — сброс), иначе юзер, не
  открывавший меню, получит ✓ из памяти.

**Вопросы человеку — закрыты (2026-10-08):**

1. Семантика — **чистый сигнал** (решение через question-tool).
2. Грязное состояние — тап по контролю внутри меню (кнопка/инпут, кроме самого крестика и ссылок)
   либо `input` со слайдера; статичный текст/заголовки не грязнят; открытие — сброс.
3. Финальный `aria-label`/title — **«Готово»** (по вердикту).
4. Undo-тост — не нужен (гибрид отвергнут в методе исключения; точечные защиты на месте: двухтап
   истории, «Убрать все» с live-счётчиком).
5. Участники — все текущие меню (шит/дровер) и будущее музыкальное из 2.23; реализовано общим helper
   `morphClose` + `wireDirty`, для новой карточки — те же две строки вызова.
