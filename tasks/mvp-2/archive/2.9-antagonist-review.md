# 2.9 Скилл «антагонист-ревьюер»: обход проекта по паттернам → отчёты в tmp

Статус: DONE (2026-10-05)

> Реализовано: `.opencode/skills/code-review/SKILL.md` + `patterns.md` (10 секций-паттернов: SOLID,
> DRY, KISS, YAGNI, FSD, tests/BDD, fail-fast, readability, security, SDD) + агент
> `.opencode/agents/pattern-reviewer.md` (mode: subagent — 1 паттерн = 1 саб = 1 отчёт). Запуск:
> попросить «ревью проекта по паттернам» или сказать «код-ревью» → скилл сам гоняет сабы и собирает
> `tmp/review/<дата>/`. Порядок: обсуждение сводки → принятые пункты в `tasks/`. Основа чек-листов —
> Google eng-practices + стабильная классика (SOLID/DRY/YAGNI); после правки `.opencode/` —
> перезапустить opencode.

## Цель

Скилл, который **только ревьюит и отдаёт отчёт** (никакой автоматической правки кода): проходит по
проекту, ищет узкие места разработки, сверяет код с набором паттернов
(SOLID/DRY/KISS/YAGNI/FSD/SDD/BDD — стартовый список, расширяется). Для каждого паттерна можно
запускать отдельного саба, чтобы не размазывать контекст. На выходе — отчёты в папке `tmp/` с
таймлайнами. Дальше **человек + агент совместно** решают, что делать, что нет и почему; получается
план; реализация — когда будет время и желание.

## Контекст

- Правила скиллов/агентов: `AGENTS.md` (раздел «opencode: скилы, агенты, тулы») + официальная докa
  (<https://opencode.ai/docs/skills/>, `/docs/agents/>`). Скилл —
  `.opencode/skills/<name>/SKILL.md`, frontmatter `name` + `description` («Use when…», триггер-слова
  в начале). Пример существующего: `.opencode/skills/ui-review/SKILL.md`.
- Сабы = subagent-агенты (`.opencode/agents/<name>.md`, `mode: subagent`) **или** встроенный Task
  tool с кастомным prompt — приёмка не привязан к механизму, но саб на паттерн должен запускаться
  отдельно (1 паттерн = 1 проход = 1 отчёт).
- `tmp/` — песочница, в git не идёт (правила в `AGENTS.md` + `tmp/README.md`); отчёты класть в
  `tmp/review/<дата-время>/<паттерн>.md` (таймлайн: что смотрели, где нашли, когда).
- Паттерны — данные, не хардкод: список описывается в самом скилле (секция «Паттерны») или отдельным
  md рядом; стартовый набор: SOLID, DRY, KISS, YAGNI, FSD (слои `src/` — `docs/ARCHITECTURE.md`),
  SDD (связь со спеками `specs/` из задачи 2.8), BDD (приёмки в `tasks/` vs тесты).
- Слои/границы проекта для FSD-проверок: `docs/ARCHITECTURE.md` (таблица «куда класть», импорты вниз
  по слоям); это же — источник «правил» для сабов.

## Требования

1. Скилл `.opencode/skills/code-review/` (имя уточнить):
   - триггеры: «ревью проекта», «пройди по паттернам», «антагонист» и т.п.;
   - описывает процедуру: выбрать паттерны → на каждый паттерн запустить саба → собрать отчёты →
     выдать сводку человеку;
   - явно запрещает править код: на выходе только отчёт (ревью ≠ рефакторинг).
2. Саб-проходы: каждый саб получает определение паттерна + список файлов/слайсов для обхода и
   возвращает: находки (файл:строка), severity, почему это проблема именно по этому паттерну,
   предлагаемое направление (не готовое решение).
3. Отчёты: `tmp/review/<ISO-дата>/` — по файлу на паттерн + `summary.md`; в каждом — таймлайн обхода
   (что просмотрено, в каком порядке, сколько заняло) и findings с приоритетом. Сводка для человека:
   топ-N «стоит / не стоит» с аргументами сторон.
4. Формат решений: после отчёта — сессия человек+агент «что берём в план, что отклоняем и почему»;
   принятые пункты переносятся в `tasks/` (READY) или `docs/PLAN.md`. Скилл сам ничего не планирует
   и не реализует.
5. Расширяемость: добавить паттерн = дописать секцию в md (1 абзац: что проверяем, как искать); без
   правки кода скилла.

## Приёмка

- Запуск скилла с набором «DRY + FSD» даёт `tmp/review/<дата>/dry.md`, `fsd.md`, `summary.md` — с
  таймлайнами и findings `файл:строка`; код проекта не изменён.
- Каждый паттерн действительно гоняется отдельным сабом (в отчёте видно, кто что смотрел).
- В `summary.md` есть раздел «в план / отклонено» с полями для решения (пустые до обсуждения).
- Добавление нового паттерна (напр. FAIL-FAST) — только правка md-секции.
- `npx tsc --noEmit`, eslint, `npm test` зелёные (скилл кода не трогает); после правки `.opencode/`
  — напомнить перезапустить opencode (нет hot-reload, правило AGENTS.md).

## Файлы

- `.opencode/skills/code-review/SKILL.md` — скилл.
- `.opencode/skills/code-review/patterns.md` (или рядом) — описания паттернов.
- Опционально `.opencode/agents/pattern-reviewer.md` — subagent-шаблон для сабов.
- `tmp/review/` — выходные отчёты (в git не идёт), правило папки — в `tmp/README.md`.
- `AGENTS.md` — не трогаем (скилл сам описывает запуск).
