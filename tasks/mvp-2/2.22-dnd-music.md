# 2.22 Фоновая музыка для ДНД: быстрый вкл/выкл атмосферы

Статус: DONE (ресёрч 2026-10-07, реализация 2026-10-07 согласована и сделана)

## Цель

Пользователи хотят **фоновую музыку для ДНД** — чтобы в один тап включать/выключать антураж игры за
столом. Задача этого этапа — **ресёрч и вебсёрч**: какие варианты мы можем предложить из бесплатных
и реально доступных в интернете источников, с учётом наших критериев (PWA-бюджет, ноль бэкенда,
лицензии). Реализация — отдельным шагом после выбора человеком.

## Что сделать (ресёрч, по протоколу `tasks/AGENT.md`)

1. Сформулировать вопрос одним предложением (напр.: «какой источник фоновой музыки для ДНД-атмосферы
   включается тапом, бесплатно и легально, не ломая PWA-бюджет и офлайн?»).
2. Вебсёрч 2–3 запросами разными словами, приоритет — официальные страницы лицензий и источников:
   - бесплатные/CC0/CC-BY библиотеки треков (ambient/fantasy/таверна/подземелье);
   - встраиваемые плееры и стримы (YouTube/Spotify/радио-эмбеды) — вес, сеть, офлайн;
   - процедурная/генеративная музыка на WebAudio (0 байт в бандле, работает офлайн);
   - уже существующие в проекте звуки (`features/roll-dice/sound.ts`) — как общий тоггл.
3. Таблица вариантов (≥2): критерии из AGENT.md — вес/precache, офлайн, юрлица (CC0/CC-BY/PD vs «не
   для коммерции»), быстрота вкл/выкл (тап из шапки?), качество/атмосферность, цена владения.
4. Метод исключения от наименее подходящего; для финального варианта — плюсы/минусы и условия, когда
   он перестанет быть верным.
5. Вердикт 5–10 строк записать в задачу (таблица + ссылки + снятые/неснятые сомнения) — и только
   потом обсуждать с человеком реализацию (UI-тоггл, хранение, префетч).

### Метод исключения (от худшего)

1. **TTRPG-спецсервисы** — не дают встраиваемого плеера с API: интеграция «тапом из нашей шапки»
   невозможна, это просто другие сайты.
2. **Deezer** — нет официального JS play/pause для виджета (проверено по
   `developers.deezer.com/musicplugins`, оф. sample требует SDK с `appId`), контента для D&D мало →
   под нашу задачу хуже всех.
3. **Spotify** — снят по жёсткому критерию: **без логина играет только 30-секундное превью**
   (источники ниже). Гость за столом без аккаунта получает обрыв через 30 с — фон неработоспособен.
   Плюс нет `setVolume`. (Вернётся, если захотим «войти через Spotify» — вне scope.)
4. **SoundCloud** — хороший API (лучший контрол: `setVolume`, `toggle`), но D&D-контента заметно
   меньше и качество плейлистов ниже; не проверены лимиты free-прослушивания. → остаётся запасным.
5. **YouTube** — остаётся: единственный, где закрыты **все** ключевые критерии (контрол без логина +
   огромный готовый D&D-фон + volume + loop-плейлист).

### Финалист: плюсы/минусы (YouTube IFrame API)

**Плюсы:** официальный API (play/pause/volume/loop), работает без логина и без 30-сек лимитов,
бесконечный D&D-фон-контент (часовые миксы, амбиент-каналы), ленивая загрузка iframe/API по первому
тапу, `origin`/nocookie-домен для privacy, тоггл = user gesture → политика автоплея не мешает.

**Минусы:** реклама в эмбедах — официально (`support.google.com/youtube/answer/132596`: доход
делится только YouTube/автор; Google рекомендует «стандартный click-to-play эмбед, а не scripted
play» — наш тап-тоггл как раз click-to-play); визуально это видео-iframe, не «невидимый аудио»; в EU
возможен consent-экран (не проверен); офлайн — эмбед не работает, фоллбэк только наш `sound.ts`
(SFX).

**Перестанет быть верным, если:** пользователю принципиальна музыка без рекламы; нужен чисто
аудио-безвидео-плеер; выяснится, что гео-блокировки/consent убивают автоплей (проверить живым тестом
в реализации).

### Сомнения (снять при реализации, живым тестом)

- **[НЕ СНЯТО]** consent/cookie-экран YouTube в EU и поведение автоплея на iOS Safari.
- **[НЕ СНЯТО]** SoundCloud free-лимиты прослушивания незалогиненного (если SoundCloud станет
  кандидатом).
- **[СНЯТО]** Spotify без логина = превью 30 с → отсеян (WordPress Spotify-докс + Spotify newsroom
  2018-09-04 + community-тред 2025-01-30).
- **[СНЯТО]** реклама в YouTube-эмбедах существует → учтено как known trade-off.

## Реализация (2026-10-07)

**Решения человека (4 вопроса UI/UX):** iframe живёт **внутри бургер-секции** (при закрытом меню
`display:none`, звук продолжается — контракт «настоящего плеера»); один дефолтный микс, тоггл только
вкл/выкл (без выбора трека); **слайдер громкости в секции меню** (дефолт 40, персист
`dice-music-vol`); **автостарта после reload нет** — первый тап пользователя и есть жест под
политику автоплея.

**Что сделано:**

- `src/features/dnd-music/music.ts` — стейт-машина `off → loading → playing ⇄ paused` + `error`;
  ленивые `youtube.com/iframe_api` и плеер (`videoId=sHA_4wfQhE8`, embeddable проверен oEmbed;
  `loop=1&playlist=ID` — официальный способ loop для одного видео); watchdog 2.5 с (+3 с на буфер)
  ловит съеденный автоплей → `paused` + тост «Нажми ещё раз»; офлайн-тап → тост без загрузки API;
  `onError`/ошибка скрипта → `error` + тост, повторный тап пересоздаёт плеер; громкость с клампом и
  фолбэком на 40 (битое хранилище/приватный режим).
- Шапка: кнопка `mtable-music` рядом со звуком (звук левее, музыка ближе к паре); спиннер при
  загрузке, акцент `#ef3124` пока играет, `aria-pressed`/динамический `aria-label`; `fitHeadStar`
  гасит **музыку первой** (на 320 она не влезает всегда, на 390 — с составом; звук уступает только в
  тесне).
- Меню: секция «Фоновая музыка» (тоггл-дубль `mtable-music-toggle`, слайдер `mtable-music-volume`
  шаг 5 ≥44px, хост iframe `mtable-music-player`, хинт про сеть/рекламу).
- Тосты 2.22: «Нет сети — музыка недоступна» / «Нажми ещё раз» / «Не удалось запустить музыку».
- Иконки `musicIcon`/`musicOff` — Material Symbols (нота/перечёркнутая), как весь `md-icon.ts`.
- Первый внешний домен в проекте (youtube.com) — лениво, только по тапу; в precache ничего.

**Доступность YouTube (probe) — решение после фидбека «пока не работает»:**

- Пользователь: при недоступном YouTube кнопки должны **гаситься с объяснением**, а не молча падать
  в тост. Выбор через вопрос — «задизейбленная», не скрытая: остаётся видимой и в Tab.
- `probeMusic()` при маунте виджета жадно грузит **тот же** ленивый `youtube.com/iframe_api` (не
  отдельный ping — один и тот же скрипт = один и тот же сигнал); успех → `avail='ok'`, отвал/таймаут
  4 с (`PROBE_MS`) → `'unavailable'`; поздний успех переворачивает обратно через `setAvail('ok')`
  внутри `onYouTubeIframeAPIReady`; ретрай по `window 'online'`, когда ещё не `'ok'`.
- Гвард в `musicTap`: при `'unavailable'` тап — no-op (тост недоступности уже объяснил причину);
  транзиентный оффлайн доступ НЕ ломает — офлайн-тост путь сохранён (e2e test1 от него зависит).
- Отображение: `aria-disabled="true"` (не нативный `disabled` — остаётся фокусируемой), в
  `aria-label` причина, иконка `music_off`, тоггл в меню → «Нет доступа к YouTube» + хинт-своп.
  **Важно:** `setAttribute('aria-disabled','true')`, не `toggleAttribute` — ARIA читает только
  `"true"/"false"`, пустое значение ни скринридер, ни CSS `[aria-disabled='true']` не матчит.
- `YT.Player` заменяет целевой элемент — хост создаётся свежим `[data-mt-target]`-div внутри врапера
  (иначе повторный слайс падает на удалённом узле); `disposeMusic` сбрасывает `avail` в `'unknown'`
  — ремаунт перепробует.
- Герметизация тестов: youtube у нас нестабилен (первый же полный e2e-прогон поймал отказ скрипта),
  поэтому e2e и чекеры-фильтровальщики консоли получили мок `iframe_api` (`e2e/m-table.spec.ts`
  beforeEach + `tmp/check/_yt-mock.mjs`): заглушка `YT` + вызов ready-колбэка; сбой сети покрыт
  отдельным тестом `route.abort`.

**Приёмка (реализации):** тогглы шапка/меню синхронны через `onMusicChange`; офлайн и ошибка сети —
детерминированные тосты (e2e с `setOffline` и `page.route`-блоком youtube); громкость переживает
reload; музыка уступает место первой (`like-fit-probe`: 320 — всегда скрыта, 390 — с составом, 768 —
видна); a11y: тап ≥44, `aria-pressed`, focus-visible, reduced-motion (спиннер — как у бургера).

**Полный прогон перед коммитом:** `npm run lint` — 0, `npm test` — **206 passed**,
`npm run test:e2e` — **24 passed**, чекеры `ui-scale`, `add-icon`, `hint-v2`, `hint-cta2-shots`,
`social-shots` (leftOrder = sound,music), `hint-align`, `like-fit-probe`, `type-scale` (тапы
музыка+слайдер), `header-fonts` — **9/9 ALL OK/exit 0**. e2e и чекеры-фильтровальщики герметичны:
youtube и GitHub API (лимит 60/ч — источник ложных 403 при повторных прогонах) замоканы.

**Задержки и сторожи (после фидбека «спиннер висит»):** тап ставит сторож `LOAD_MS` 8 с до `onReady`
(эмбед молча не загрузился → `error` + тост, иначе спиннер вечен); `onReady` сменяет его на
blocked-сторож 2.5 с (+3 с при буферизации). Тесты на все три задержки детерминированы (fake timers,
юниты) + e2e «тап → loading → playing → пауза» на функциональном моке YT (onReady в следующем тике)
— без реальной сети.
