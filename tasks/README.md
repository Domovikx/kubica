# Задачи для агентов: как брать и сдавать

Этот каталог — очередь работ, расписанная так, чтобы любой агент мог взять один файл и выполнить его
без дополнительных вопросов.

Обязательно к прочтению перед первой задачей: `tasks/AGENT.md` (ресёрч-first: вопросы решаются
поиском и методом исключения, а не гаданием).

## Как взять задачу

1. Открой `tasks/mvp-2/README.md` (обзор среза) или конкретный файл задачи.
2. У задачи должен быть статус `READY`. Статусы: `READY` → `DOING` → `DONE`. Перед стартом поменяй
   статус на `DOING` отдельным коммитом — чтобы не было гонок между агентами.
3. Прочитай целиком: разделы «Контекст», «Файлы», «Требования», «Приёмка».

## Правила выполнения (обязательно)

- Код — только по `docs/ARCHITECTURE.md` (таблица «куда класть», импорты только вниз по слоям,
  запрещены импорты вверх и между слайсами одного слоя).
- Чистая логика — сразу с тестами рядом (`*.test.ts`, Vitest).
- Перед коммитом: `npx tsc --noEmit`, `npx eslint src/`, `npm test`, `npm run build`. Всё должно
  быть зелёным.
- Pre-commit хуки (Prettier/markdownlint/ESLint) обязаны пройти.
- Коммит на русском, глаголом: что сделано + ключевая метрика (пример:
  `Парсер нотации 4d6-L/2d20kh1+5/d100: 28 тестов зелёных`).
- После мержа пометь задачу `DONE` (правка статуса в файле, отдельный мини-коммит или вместе со
  сдачей — как скажет человек).

## Глобальный Definition of Done задачи

- [ ] `tsc` чисто, ESLint чисто, `npm test` зелёный, `npm run build` ок
- [ ] Playwright-чек без ошибок консоли (если задача трогает UI)
- [ ] Тесты покрывают все ветки из раздела «Требования»
- [ ] Доки обновлены, если менялся контракт (PLAN.md, соответствующий `docs/*.md`)

## Структура

- `mvp-2/` — текущий срез: пул костей, нотация, juice.
- Следующие срезы (MVP-3, бренд) — в `docs/PLAN.md`, сюда попадут по мере готовности.
