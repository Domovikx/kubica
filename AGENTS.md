# Правила проекта

> **СТОП-ПРАВИЛО: без явной просьбы пользователя НИКОГДА не коммитить и не пушить. Не уверен,
> коммитить или нет — спроси прямо. Молча коммитить нельзя: пользователь должен успеть review, иначе
> это его расстраивает.**

## Тесты — экономим ресурсы и время

- **Полные прогоны** (`npm test`, `npm run test:e2e`, полный набор чекеров) — ТОЛЬКО перед коммитом
  и перед PR.
- В процессе разработки полные тесты **не запускать**. По необходимости — только точечные и по делу:
  конкретный файл/тест (`npm test -- <имя>`, `npx playwright test --grep <...>`), ровно то, что
  относится к текущей правке.
- Ничего гонять «на всякий случай»: тесты жрут ресурсы и время, держим расход минимальным.

## Git

- **Никогда не коммитить и не пушить без явной просьбы пользователя.** Семантические (краткие,
  русские) коммиты — только когда просят.
- Сомневаешься «надо коммитить или подождать» — **спроси явно**, не действуй по своему усмотрению.
- Когда просят коммит — сначала полный прогон тестов (см. выше), потом коммит/push.

## Временные файлы

- **Единственная tmp-папка: `C:\Users\Domo\workspace\kubica\tmp`.** Никогда не использовать `C:\tmp`
  или системный tmp: у инструментов со своим cwd (Blender, OpenSCAD) — только **абсолютные** пути
  внутрь `kubica\tmp`.
- `tmp/` — песочница (чекеры, скриншоты, отладка), в git не идёт; структура и правила запуска — в
  `tmp/README.md`. Новые скрипты-чекеры класть в `tmp/check/`.
- Отчёты Playwright — `tmp/test-results/` и `tmp/playwright-report/` (outputDir/reporter в
  `playwright.config.ts`).
- `tmp/vite-dev.log` — живой лог dev-сервера: не трогать, пока сервер работает.

## opencode: скилы, агенты, тулы — работаем по официальной доке

Источники истины (читать перед созданием/правкой):

- Скилы: <https://opencode.ai/docs/skills/>
- Агенты: <https://opencode.ai/docs/agents/>
- Кастомные тулы: <https://opencode.ai/docs/custom-tools/>
- Схема конфига: <https://opencode.ai/config.json> (правим opencode.json только после сверки со
  схемой; резюме — скилл `customize-opencode`)

### Скилы

- Проектный путь: `.opencode/skills/<name>/SKILL.md` — папка на скилл, файл ровно `SKILL.md`.
- Frontmatter обязателен: `name` (= имя папки, `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤64) и `description`
  (1–1024, третье лицо «Use when…», trigger-слова в начале) — без description скилл агент не увидит.
- Тело — markdown-инструкции; относительные пути считаются от папки скилла.

### Агенты

- Нестрivialное — файлом `.opencode/agents/<name>.md` (имя файла = имя агента), не инлайном в
  opencode.json.
- Frontmatter: `description` (обяз.), `mode: primary|subagent|all`, `model: provider/model-id`,
  `permission`, `steps`, `temperature`. Тело файла = prompt; ключ `prompt` во frontmatter НЕ
  дублировать.
- Встроенные (build/plan/general/explore) переопределяем точечно — только нужные поля.

### Тулы

- `.opencode/tools/<name>.ts` — default export `tool()` из `@opencode-ai/plugin`; имя файла = имя
  тула; аргументы — Zod-схемы с `.describe()`.
- Имена не перезаписывают built-in осознанно; отключать built-in — через permissions.

### Правила проекта

- `.opencode/` (skills/agents/tools) — в git; `node_modules/` покрыт корневым .gitignore. Пакетов
  тут нет: `package.json`/`@opencode-ai/plugin` не ставим — зависимости для тулов добавляем только
  если реально начнём их писать.
- После любой правки конфига/скиллов/агентов/тулов — напомнить перезапустить opencode (hot-reload
  нет, конфиг читается при старте).
- `$schema` в opencode.json обязателен; `instructions: ["AGENTS.md"]` уже подключён.
