## Требования (из разговора)

1. Готовое, удобное для НЕтехнических пользователей (игроки, не разработчики).
2. Голосование за фичи (чтобы спрос измерялся сам).
3. Ноль наших ресурсов на чтение: агент забирает фидбек через MCP, дашборды не открываем.
4. PWA-дружелюбно: ссылка/виджет из приложения, работает с телефона.

## Рекомендация: два контура, оба бесплатные

1. **GitHub Discussions** — система записей и голосовалка по умолчанию. Категории: `Ideas`
   (голосование), `Q&A`, `Show & tell` (сеты пользователей), `Bug reports` (шаблон: ID модели +
   скриншот — у нас уже есть ID!). Ссылка «Предложить фичу» в футере приложения → сразу в Ideas.
2. **Telegram** — быстрый контур для RU: анонсы + опросы-голосовалки, ссылка из PWA. Результаты
   вручную (или ботом) переносим в Discussions.
3. Платные Canny/Frill — только когда фидбека станет >~50 постов/мес и понадобится роадмап-витрина.

## MCP: читаем фидбек не открывая браузер

В `opencode.json` рядом с blender/freecad/cadquery добавляется:

```json
"github": {
  "type": "local",
  "command": ["uvx", "mcp-server-github"],
  "enabled": true,
  "environment": {
    "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
  }
}
```

[УТОЧНИТЬ точное имя пакета/команды на момент внедрения — экосистема MCP быстро меняется; инвариант:
официальный GitHub MCP с tools для discussions.] Ритуал триажа (раз в неделю, делает агент): забрать
топ по upvote → сгруппировать дубликаты → завести ишью/задачи в todo → ответить шаблоном «взято в
бэклог / нужно уточнение». Человеко-часы: ~0.

Для Telegram: Bot API → тот же ритуал (прочитать опросы через `getUpdates` или готовый
telegram-MCP). Секрет бота — в env, не в репозиторий.
