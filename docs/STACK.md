# STACK: почему ванила — замеры, а не мнение

Дата: 2026-09-22. Статус: решение зафиксировано. Веб-поиск недоступен из песочницы (403), поэтому
вместо чужих статей — собственные замеры esbuildminify на эквиваленте нашего UI (список с
чекбоксами + стейт). Методология: `esbuild --bundle --minify`, размер min и min+gzip. Повторить:
любой `npx esbuild entry --bundle --minify`.

## Замеры (байты)

| Что                                 | min                     | gzip     | Доля к нашему коду             |
| ----------------------------------- | ----------------------- | -------- | ------------------------------ |
| Наш код (FSD-модули, без three/CSS) | 7 868                   | 2 897    | 1× (база)                      |
| three.js (факт. доля в бандле)      | ~635 000                | ~158 000 | 55×                            |
| React 19 + ReactDOM                 | 222 920                 | 69 148   | +24× к коду, +43% к скачиванию |
| Vue 3                               | 64 638                  | 25 633   | +9× к коду, +16% к скачиванию  |
| Preact (+hooks)                     | 12 894                  | 5 372    | +2× к коду, +3% к скачиванию   |
| Svelte 5 / Solid                    | ~0 runtime (компилятор) | ~0       | цена — тулчейн, а не байты     |

Текущий прод-бандл: 643 КБ min / 161 КБ gzip (практически весь — three.js).

## Решение: ванила + three.js. Почему

1. **Наш UI — 2.9 КБ gzip.** Чекбоксы, грид панелей, 2 кнопки, история бросков (MVP-1). Фреймворк
   стоил бы от 2× (Preact) до 24× (React) всего нашего кода — платить не за что: нет форм, роутинга,
   списков на тысячи строк.
2. **PWA-бюджет.** Каждый килобайт — миллисекунды TTI на 3G и байты precache. Тяжёлое уже оплачено
   (three.js неизбежен — это и есть «фреймворк» для 3D).
3. **Стабильность API.** three.js миноры ломают аддоны; лишний слой (обёртки React-Three-Fiber и
   т.п.) удваивает поверхность поломок. Прямой three + FSD-модули — минимум посредников.
4. **Это не «фреймворки плохи».** Svelte 5 / Solid решили бы вопрос веса (компилятор вместо
   рантайма) — но принесли бы тулчейн ради сотни строк кода. Невыгодный обмен на текущем размере.

## Триггеры пересмотра (когда ванила перестанет хватать)

- Общие комнаты/аккаунты/синхронные броски (фаза 2 BUSINESS.md): формы, сокеты, сложный стейт →
  переоценить (кандидат: Svelte — малый вес).
- UI-стейт перерастёт ~500 строк в `features/`+`widgets/` или появится второй независимый экран с
  формами.
- Команда >1 человека с опытом конкретного фреймворка.

До тех пор: FSD + TypeScript strict + ESLint дают структуру без фреймворка.
