# AUDIO: звук бросков, озвучка результатов, доступность

Дата: 2026-09-22. Статус: ресёрч для обсуждения (MVP-1/UX_ROLL.md). Веб-поиск недоступен из
песочницы — ниже инженерные знания + пометки [ПРОВЕРИТЬ] там, где нужен факт из стора/спеки.

## Принцип: ноль аудиофайлов

Все звуки синтезируются через Web Audio API в рантайме. Почему:

- PWA-офлайн из коробки (нечего precache'ить, см. PERF.md — бюджет цел);
- 0 байт трафика и 0 вопросов лицензирования сэмплов;
- параметры звука = пресет (см. «звуковые паки» в UX_ROLL.md §4).

## Какие звуки нужны (минимум MVP-1)

| Звук                   | Синтез                                                            | Триггер                          |
| ---------------------- | ----------------------------------------------------------------- | -------------------------------- |
| Грохот костей (rattle) | короткие шумовые всплески (bandpass noise), темп/питч от скорости | пока суммарная скорость > порога |
| Глухой «ток» остановки | затухающая синусоида 180–260 Гц + щелчок                          | каждое тело уснуло (sleep event) |
| Клик UI                | 5–10 мс square blip                                               | кнопки/чекбоксы                  |
| Фанфары крита (nat20)  | арпеджио 3–4 ноты треугольником                                   | результат 20                     |
| Грустный тон (nat1)    | нисходящий слайд                                                  | результат 1                      |

Громкость каждого слоя — от физики: питч/темп rattle ∝ скорости, «ток» громче для d20 (масса
больше). Это и есть «залипательность» из UX_ROLL.md §3 — звук продаёт физику сильнее картинки.

## Озвучка результатов голосом (TTS)

- `speechSynthesis` — бесплатно, без сети (голоса зависят от ОС): `utterance.lang` = текущая локаль
  (см. I18N.md), rate ~1.1.
- По умолчанию ВЫКЛ, включается в настройках («объявлять результат»). Отдельный тоггл от игровых
  SFX.
- [ПРОВЕРИТЬ]: качество/наличие офлайн-голосов RU на Android (Google TTS обычно есть) и iOS
  (Samantha и др. — докачиваются в настройках ОС).

## Screen reader — отдельно от игрового звука

- Результат дублируется в `aria-live="polite"` регион (см. UX_ROLL.md §4, I18N.md) — это не
  `speechSynthesis`, а штатный скринридер пользователя.
- Декоративные звуки помечаем `aria-hidden`, кнопки — текстовыми метками.

## Технические ограничения (граничные случаи)

1. **Автоплей-политика:** Chrome/Safari требуют жеста пользователя — `AudioContext` создаём лениво
   на первом тапе («бросить»), до этого молчим.
2. **iOS silent switch:** в беззвучном режиме WebAudio может глушиться — тестировать на реальном
   iPhone; фолбэк — вибрация (`navigator.vibrate`).
3. **Фон/экран выкл:** звук броска не должен играть из фона — глушим вместе с rAF-циклом (см.
   PERF.md §5).
4. **Производительность:** синтез — десятки осцилляторов, CPU ~0%; утечки — закрывать ноды
   (`stop()` + `disconnect()`), один shared `AudioContext` на приложение.
5. **Вибрация:** паттерн на остановке, двойной на крит; отдельный тоггл; десктопы без вибромотора
   просто игнорят вызов.
