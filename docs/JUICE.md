# JUICE: почему залипают и что крутим у костей

Дата: 2026-09-23. Вопрос: анимация броска слишком быстрая и не «залипает» — что по науке делает вещи
залипательными (спиннеры, чётки) и что из этого честно применить у нас.

## Факты (проверено 2026-09-23)

- **Переменное подкрепление** (Wikipedia, Operant conditioning): variable-ratio schedule даёт «very
  high, persistent rate of response» — механика слот-машин. У нас вариативность уже есть в самих
  костях (честный рандом), дополнительно расписание наград **не крутим** — см. запрет гемблинга
  ниже.
- **Немедленность** (там же, factors: immediacy): отклик сразу после действия учит быстрее. Тап →
  грохот и движение в том же кадре, без задержек инициализации.
- **Тактильность как вторичное подкрепление** (там же): haptic-вибрации с мобилок работают как
  learned rewards. Прямое обоснование вибрации на остановке (уже было в AUDIO.md).
- **Поток** (Wikipedia, Flow, Csikszentmihalyi): ясные цели + немедленный фидбек + поглощение;
  искажение времени — маркер, что залипло. Наш цикл «тап → 2–3 с болида → поп результата» ровно эта
  формула.
- **Физика спиннера** (Wikipedia, Fidget spinner): угловой момент + затухание скорости по
  **экспоненте**. Именно длинный экспоненциальный хвост (резкий старт → долгое успокоение), а не
  линейное торможение, выглядит «залипательно». Ось при этом стабильна (гироскоп), а не кувырок по
  трём осям.
- **Честная оговорка** (там же): исследования НЕ подтвердили пользу спиннеров для фокуса/СДВГ. Нам
  важен фан броска, не терапия — так и пишем.

## Решение (метод исключения)

| Вариант                                                                                                                        | Вердикт                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| A. Экспоненциальный спин вокруг стабильной оси ~2.2 с + дотяжка 0.45 с + бит паузы 0.2 с, поп/тук/вибро строго в момент settle | **Берём**: чистая презентация, бюджет ≤3 с держим, детерминировано                                    |
| B. Slow-mo nat20/nat1, конфетти, скриншейк                                                                                     | Позже, это задача 2.4                                                                                 |
| C. Стрик-награды, лутбоксы, подсветка «почти 20» (near-miss)                                                                   | **Reject**: манипуляция расписанием подкрепления, убивает позиционирование честности (BUSINESS.md §7) |

## Что закодировано

- `viewer.ts`: спин `ω(t) = ω₀·e^(−t/τ)`, ω₀=15 рад/с, τ=0.65 с (≈2.2 с видимого движения), ось одна
  стабильная на бросок; settle — time-based 450 мс (не зависит от Гц экрана).
- `viewer-grid.ts`: минимальный спин 2 с (физика обычно готова за ~1.2 с — ждём визуал, иначе поп
  спойлерит результат раньше дотяжки); тук + вибрация + поп — в конце settle.
- `sound.ts`: стуки реже и тише к концу (decrescendo интервалов — кость «теряет энергию»).
- `quick-roll.ts`: опция `silent` (без попа/звука) для бросков с витриной; история пишется всегда.

## Как проверить залипание

Количественно: повторные тапы и рероллы на сессию (события `reroll_from_history`, pool_size — см.
UX_ROLL.md §1). Качественно: «время пролетело» (искажение времени = маркер потока). Бюджет
guardrail: тап → читаемый результат ≤3 с, иначе juice бесит на 50-м броске.
