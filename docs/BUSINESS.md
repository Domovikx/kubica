# Бизнес-план: 3D-дайсы PWA — честные кубики в браузере

Дата: 2026-09-22. Статус: черновик для обсуждения.
Источники цифр: Wikipedia (D&D — 12–15 млн игроков в Сев. Америке на 2017, 9 млн
зрителей Twitch; 2020: 39% женщин, 40% Gen Z, онлайн-игра +86%), открытые данные
индустрии. Точные ёмкости сегментов — пометки [УТОЧНИТЬ].

## 1. Продукт и позиционирование

**Что:** бесплатное веб-приложение (PWA) — бросок настоящих 3D-кубиков d4–d20
в браузере, работает офлайн. Кубики — не «нарисованные», а реальные CAD-модели
из этого репозитория: измеренный центр масс (смещение 0.0004–0.0023 мм, см.
RESEARCH.md §6), открытые STL, честная геометрия.

**Позиционирование:** «честные дайсы» (honest dice). Все конкуренты бросают
«какую-то 3D-модель»; мы бросаем модель, чью геометрию и баланс можно проверить:
открытые файлы + опубликованные замеры. Для настольщиков честность кубика —
эмоционально главный аргумент (ср. культ GameScience с острыми гранями).

**Почему PWA, а не нативное приложение:** ноль установки из стора, одна кодовая
база (десктоп + Android + iOS), офлайн из коробки, обновления без ревью сторов,
хостинг почти бесплатный (GitHub Pages + CDN). Магазины — позже, при желании,
обёрткой (PWABuilder/Bubblewrap).

## 2. Спрос: кому и зачем (сегменты и кейсы)

### Сегмент A. НРИ-игроки за столом (ядро)
- **Кейсы:** забыл кости дома; нет нужного дайса (d100 из двух d10); ночная
  партия без грохота по столу (вибро/звук вместо стука); DM кидает скрытно
  за ширмой с телефона.
- **Размер:** D&D — 12–15 млн игроков только Сев. Америка (2017), рост все
  2010-е, BG3/Stranger Things привели новую волну; 40% — Gen Z
  (мобайл-first). [УТОЧНИТЬ свежие цифры 2024–2026.]
- **Боль:** существующие роллеры уродливы (2D) или привязаны к экосистеме
  (D&D Beyond — только подписчикам по-настоящему удобен; Roll20 — команды в чат).

### Сегмент B. Онлайн-партии (VTT-компаньон)
- **Кейсы:** быстрый бросок рядом с Roll20/Foundry/Discord без переключения
  контекста; шаринг результата ссылкой/скриншотом; бросок «на доверии», когда
  физику видно всем (стрим).
- **Размер:** онлайн-игра +86% в 2020 (LA Times via Wikipedia); Roll20 —
  миллионы аккаунтов [УТОЧНИТЬ].

### Сегмент C. Настольщики вне НРИ
- **Кейсы:** заменить потерянный d6/d20 в коробке; обучение вероятности
  (школа/кружки — наглядные 3D-кубики + история бросков); соло-игры,
  требующие редких дайсов (d12, d100).
- **Размер:** весь рынок настолок — десятки млн покупателей в год [УТОЧНИТЬ].

### Сегмент D. Мейкеры/коллекционеры (мост в наш CAD-пайплайн)
- **Кейсы:** посмотреть кастомный сет до печати; скачать STL своего сета
  и напечатать; заказать печать (print-on-demand).
- **Размер:** ниша, но самая платёжеспособная; у нас уже есть генератор
  (`tools/dice_set.scad`) — естественная воронка «посмотрел → скачал STL →
  напечатал/заказал».

### Сегмент E. Доступность (a11y)
- **Кейсы:** слабовидящие (крупный результат, озвучка через screen reader),
  проблемы с моторикой (одна кнопка вместо горсти костей).
- Не сегмент выручки, но сильный аргумент для продвижения и отзывов.

## 3. Конкуренты и наши отличия

| Конкурент | Что умеет | Слабость → наше окно |
|---|---|---|
| D&D Beyond (цифровые дайсы) | роллы в листе персонажа | привязка к экосистеме/подписке; 2D |
| Roll20 / FoundryVTT (базовые роллеры) | бросок в чате партии | нет красивой 3D-физики из коробки |
| Dice So Nice! (модуль Foundry, 3D-физика) | эталон 3D-бросков в VTT | только внутри Foundry; модели «художественные», без заявления о честности геометрии |
| Мобильные «3D Dice Roller»-апплеты | просто | реклама во весь экран, нет офлайна/кастомизации, сомнительная физика |
| Физические кости (Chessex и др.) | тактильность, коллекционирование | надо носить/покупать;complement, а не враг (партнёрки, принт) |

**Наши отличия (защита):** открытые CAD-модели + опубликованные замеры CoM;
офлайн-PWA без аккаунта; кастомайзер → STL → печать (замкнутый цикл, которого
нет ни у кого из таблицы).

## 4. UI/UX: требования по сегментам

Базовый принцип: **бросок за один тап**. Всё остальное — не дольше двух тапов.

- **Бросок:** большая кнопка/тап по кубику; тряска телефона (shake-to-roll,
  с отключением); крупная цифра результата + анимация кувырка с физикой.
- **Нотация:** парсер `4d6-L`, `2d20kh1`, `d100`, модификаторы `+5`; пресеты:
  advantage/disadvantage, статы `4d6 drop lowest`, инициатива.
- **История:** лента бросков (что/когда/сколько), шаринг результата.
- **Кастомизация:** темы материалов/цвета на кость; крупный шрифт результата.
- **Офлайн:** явный бейдж «работает без сети»; весь сет GLB (~4 МБ) + движок
  (~0.6 МБ) в precache.
- **Доступность (WCAG):** live-region объявляет результат для screen reader;
  выключатели звука/вибрации/автоповорота; `prefers-reduced-motion` глушит
  анимацию; контраст текста; тач-цели ≥44px.
- **Никогда:** реклама/пейволл, прерывающие бросок (см. §7).

## 5. PWA: техтребования и ограничения

- **Сборка:** `vite-plugin-pwa` (Workbox), precache: модели + three.js;
  бюджет кэша ~10 МБ (влезаем: сет ~4 МБ + сравнение + бандл 0.6 МБ).
- **Ограничения iOS:** нет install-промпта и пушей — компенсируем своим
  экраном «добавить на домой»; лимиты кэша Safari — держим precache ≤25 МБ.
- **Метрики:** install conversion, % сессий офлайн, TTI на 3G.
- **Десктоп:** устанавливается как приложение (Chrome/Edge), иконки+маска.

## 6. Границы, честность, право

- **Честность, которую заявляем:** открытая геометрия + измеренный CoM
  (0.0004–0.0023 мм) + криптографический RNG (`crypto.getRandomValues`) для
  выбора исхода; физика — визуализация. **НЕ заявляем:** сертификацию уровня
  казино, «доказанную» случайность симуляции.
- **Гемблинг:** позиционирование строго «дайсы для настольных РПГ и игр»,
  без ставок, без выигрышей, без валюты. Дисклеймер в футере/About. Это держит
  вне регулирования азартных игр в большинстве юрисдикций [проверить у юриста
  перед монетизацией].
- **Приватность:** без аккаунта и трекинга по умолчанию; аналитика — только
  агрегированная и опциональная (типа Plausible), куки-баннер не нужен.
- **Возраст/контент:** 0+, ничего чувствительного.

## 7. Монетизация (ненавязчивая)

Принципы: бесплатны навсегда — все броски, все базовые кости, офлайн.
Реклама **никогда** не прерывает бросок (максимум — маленькая строка в меню).
Никакого pay-to-win (у кубика нечего выигрывать).

| Поток | Что платное | Оценка |
|---|---|---|
| Freemium-кастомизация | премиум-материалы/темы, своя гравировка (имя на d20), наборы художников | основной цифровой доход |
| STL-экспорт для печати | бесплатно — превью/свой сет; платно — высокое разрешение/коммерческая лицензия | мост в мейкеров (сегмент D) |
| Print-on-demand | партнёрство с печатными сервисами, % с заказа своего сета | самый «физический» доход |
| Аффилиаты | ссылки на физ. кости/аксессуары (не конкуренция, а «потрогай настоящее») | копейки, но к месту |
| Донаты | Ko-fi/Patreon/Boosty «на хостинг и новые сеты» | лояльность комьюнити |

Что НЕ делаем: лутбоксы/гача на дайсы, продажа «более удачливых» костей
(убило бы позиционирование честности), interstitial-рекламу.

## 9. Масштабирование и затраты

- **v1 (сейчас):** чистая статика — хостинг ~0 ₽/мес (GH Pages), CDN включён,
  бэкенда нет, масштабирование = бесплатно по определению.
- **Фаза 2 (опционально):** общие комнаты/синхронные броски для онлайн-партий —
  WebRTC (P2P, почти бесплатно) или минимальный WS-бэкенд (тогда появятся
  первые серверные затраты ~$5–20/мес + модерация комнат).
- **Узкие места роста:** вес precache (следить ≤25 МБ), число WebGL-контекстов
  (сейчас ≤9 на странице просмотра — в роллере будет 1 сцена, проще).

## 10. Метрики успеха

- Активация: % посетителей, сделавших первый бросок (<30 сек?).
- Вовлечение: бросков/сессия, возврат D1/D7/D30.
- PWA: install conversion, доля офлайн-сессий.
- Качество: NPS/звёзды, inbound-фидбек (как сейчас — по ID моделей!),
  0 критов в консоли.
- Деньги (позже): конверсия в платную кастомизацию, ARPPU, доля STL-экспортов.

## 11. Риски и открытые вопросы (к обсуждению)

1. Нужен ли вообще отдельный роллер при живых D&D Beyond/Roll20? → ставка на
   офлайн + честность + кастомизацию, которых у них нет.
2. i18n: сначала RU или сразу EN? (охват EN на порядок больше).
   → См. I18N.md: автоопределение по локации (RU/EN) + TOP-10, остальное позже.
3. Физика броска: честная симуляция (cannon-es/rapier) vs «красивая анимация +
   честный RNG»? (дешевле и честнее второе; физика — для стримеров/доверия).
   → См. UX_ROLL.md §3 (там же ресёрч залипательной анимации и MVP-нарезка).
4. Печать: свой принтер/партнёр или только STL-маркет?
5. Валидация спроса до кода: лендинг + форма «что вам нужно», опросы UX
   (вопросы — в UX_ROLL.md §1), аналитика событий (§10 + UX_ROLL.md §1).
6. Переключение 1-vs-N кубиков: какой паттерн по умолчанию — решить по данным
   (UX_ROLL.md §1–§2).
